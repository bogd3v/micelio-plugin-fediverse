# Data classification and protection

**Kind:** reference. The data this plugin holds, the three protection levels it sorts them into, and what each level requires. The levels and their names are those of `docs/security/data.md` of `bogd3v/micelio-cms`, which the rows below were carried over from; the keys are in [keys.md](keys.md) and the log lines in [logging.md](logging.md). What the host holds besides (accounts, comments, tokens) is the host's to classify.

## Levels

| Level          | What it is                                                               | Requirements                                                                                                                                                                                                                         |
| -------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Restricted** | A credential or a single-use secret: whoever holds it can act as someone | Never returned by an API, never logged, never in a response to another person. At rest only encrypted, where the table below says so.                                                                                                |
| **Personal**   | Data about an identifiable person                                        | Collected because a feature needs it. Returned only to moderators and editors in the admin panel. Not logged, except numeric ids. Leaves the server only to the servers of the people it describes. Kept while its feature needs it. |
| **Public**     | Published content and aggregated counts                                  | Served as published.                                                                                                                                                                                                                 |

## What is held

Every row of a content type of the plugin belongs to one site (`site`, a required relation made by `withSiteScope` of `@micelio/strapi-plugin-core`), and so does the actor key: a site's data is read and written only through that site. A site never sees another's followers, interactions, federation state or key. The classes below are those `micelio-cms` 0.6 gave the same data; the site relation is a pointer to a site, not data about a person, and adds no class.

| Data                                                                    | Level      | Where (store, type, attribute)                                                                                                              | Protection in place                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Fediverse actor private key, one per site                               | Restricted | Strapi core store, plugin `fediverse`, key `keyPairs:<site documentId>`                                                                     | AES-256-GCM with `ENCRYPTION_KEY`; the public key stays plain. The entry kept under `keyPairs` before the sites stays too, for one release line, encrypted the same way ([keys.md](keys.md)); backups and free database pages written before encryption at rest still hold the plain JWK                                                               |
| Fediverse actor public key, one per site                                | Public     | Same entry                                                                                                                                  | Published in the actor document by design                                                                                                                                                                                                                                                                                                              |
| Fediverse delivery queue and caches                                     | Restricted | PostgreSQL tables `fedify_message_v2`, `fedify_kv_v2`; memory on SQLite                                                                     | Each queued message carries the actor's signing key encrypted with `ENCRYPTION_KEY` and the follower's inbox URL; it is deleted when taken for delivery. Not keyed by site: the actor id does not change                                                                                                                                               |
| Remote followers                                                        | Personal   | `plugin::fediverse.follower`: `actorId`, `handle`, `name`, `inbox`, `avatar`, `blocked`, `site`                                             | Belong to people on other servers. Remote text is cleaned before it is stored or logged (`server/src/utils/remote-text.ts`). Read only through the site they follow                                                                                                                                                                                    |
| Follower unreachable flag (when its inbox was last found gone)          | Personal   | `plugin::fediverse.follower`: `unreachableSince`                                                                                            | Cleared when the follower sends an activity again. Fan-outs skip a flagged follower; the followers collection still lists it                                                                                                                                                                                                                           |
| Followers and blocks in an export archive (`--include fediverse`)       | Personal   | `plugins/fediverse/followers.json` of the site archive: `actorId`, `handle`, `name`, `inbox`, `blocked`                                     | Off by default (`personalData: true`): written only when asked for by id, needs `plugin::fediverse.manage`, and the core logs every export that includes it. No avatar, no unreachable flag, no date, no key. On import the text is cleaned and URLs checked as for a remote server, and a block is never lifted. The archive is handled like a backup |
| Followers on the Fediverse page                                         | Personal   | Read by admins with `plugin::fediverse.read` (route `GET /fediverse-panel/followers`, optional `?site=<slug>`)                              | Handle, name, date of the follow, blocked and unreachable only: no actor id, inbox or avatar. Changing a block needs `plugin::fediverse.manage`, and a follower of another site is "no such follower"                                                                                                                                                  |
| Remote likes and boosts (actor id, handle, interaction key)             | Personal   | `plugin::fediverse.interaction`: `actorId`, `handle`, `interactionKey`, `site`; `type` and `articleDocumentId` are public                   | Belong to people on other servers. The public counters aggregate them, per site, and never say who interacted                                                                                                                                                                                                                                          |
| Federation state of an article (last activity, when, with what outcome) | Public     | `plugin::fediverse.federated-article`: `articleDocumentId`, `status`, `lastActivityAt`, `lastActivityType`, `attempts`, `lastError`, `site` | `lastError` is sanitised: no query string, no IP literal, no email. Shown to admins with `plugin::fediverse.read`                                                                                                                                                                                                                                      |

The three content types are never written as content of the core's archive (`pluginOptions.micelio.export: "never"`): the actor key, the interactions and the federation state of the articles are not exported, and followers only through the section above.

The plugin writes no personal data to the log: the step that gives the default site what the plugin stored before the sites logs counts only ([logging.md](logging.md)).
