# Release notes and upgrade notes: 0.7.0

**Kind:** how-to. The release notes of `@micelio/strapi-plugin-fediverse` `0.7.0` (a breaking change before 1.0.0: standard, section 7), from the plan in `docs/architecture/fediverse-cut-over.md` of `bogd3v/micelio-cms`. The Release workflow takes the Compatibility bullets and the upgrade notes below as its `compatibility` and `upgrade_notes` inputs.

## Compatibility

- Declares the Micelio release line `0.7` (`"micelio": "0.7"` in `package.json`).
- Tested with `@micelio/strapi-plugin-core` `0.2.0` (peer range `^0.2.0`), Strapi `5.59.0` and `strapi-plugin-comments` `3.2.4`. The core release that declares the `0.7` line, and a peer range that admits it, come later.
- Node `>=22.19.0`.
- PostgreSQL `14` or later, the minimum Strapi 5 documents for its PostgreSQL support, for the durable delivery queue (the two PostgreSQL suites were not run on a stated version in this release). SQLite works without the durable queue: deliveries then wait in memory and a restart loses them ([configure.md](configure.md#delivery-queue-and-database-connections)).

## What changes

- **One actor per site** (breaking): the actor, its key, followers, interactions and federated articles belong to a site; the handle and the attribution domains come from the site's `hosts`.
- **The Fediverse page** is in the Micelio sub-navigation and the plugin's admin entry registers it and the article panel (breaking for the host: below).
- **Status and export.** The Micelio Status page has a Fediverse card per site (public address, actor key, WebFinger), and `micelio export --include fediverse` writes the followers and their blocks (never the key); see [configure.md](configure.md#status-and-export).
- **Articles federate on the core's hooks.** For an article type made with `withEditorial`, the plugin federates on the core's `afterPublish` and `afterUnpublish` and ignores `entry.publish` and `entry.unpublish`: one trigger per type, no double send. See [configure.md](configure.md#move-the-article-to-the-editorial-workflow-without-a-double-send).
- **Published on npm.** The package is no longer private.

## Upgrade notes

> **Fediverse: settings move into the site.** Federation is still off unless `FEDIVERSE_ENABLED=true`. Your followers, their blocks, the delivery queue and the actor key are kept; the actor id and the handle do not change. Take a backup first. The stored federation data moves to the default site on the first 0.7 boot: the log line to check and the rollback are in [configure.md](configure.md#upgrading-to-07-the-federation-state-belongs-to-a-site).
>
> What stops working, and what to set instead. Move the four `FEDIVERSE_ACTOR_*` values **before** you upgrade, in the 0.6 admin: a 0.7 boot with one of them set stops with a message that names it. The first 0.7 boot that finds the default site pins your current handle host (`FEDIVERSE_HANDLE_HOST`, or the host of `URL` when it is unset) as the first of the site's hosts and records that it did (the plugin store key `plugin_fediverse` / `cut-over-0.7`); later boots ignore the variable with a warning that names it. Remove it afterwards.
>
> | Remove                       | Set instead                                                                                                                                                                                                                                                                                                                                                                                                                              |
> | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
> | `FEDIVERSE_ACTOR_USERNAME`   | Content Manager → Sites → your site → **Fediverse** → **Username**                                                                                                                                                                                                                                                                                                                                                                       |
> | `FEDIVERSE_ACTOR_NAME`       | The same profile, **Display name**                                                                                                                                                                                                                                                                                                                                                                                                       |
> | `FEDIVERSE_ACTOR_SUMMARY`    | The same profile, **Summary**                                                                                                                                                                                                                                                                                                                                                                                                            |
> | `FEDIVERSE_ACTOR_SOURCE_URL` | The same profile, **Source URL**                                                                                                                                                                                                                                                                                                                                                                                                         |
> | `global.fediverseHeader`     | The same profile, **Header**                                                                                                                                                                                                                                                                                                                                                                                                             |
> | `FEDIVERSE_HANDLE_HOST`      | Content Manager → Sites → your site → **Hosts**: the handle host is the **first** one. The first 0.7 boot sets it from your 0.6 handle host (the old variable, or the host of `URL` when it was unset): it fills an empty list or moves that host to the front of a filled one, so your handle and its WebFinger keep working. If another site already holds that host, the boot stops with a message that names the variable (or `URL`) |
> | the attribution domains      | Nothing to configure: the actor lists every host of the site. The boot adds the CMS host (when you never set `FEDIVERSE_HANDLE_HOST`) and the host of `FRONTEND_URL`, after the handle host (logged, not a stop, if another site holds the latter)                                                                                                                                                                                       |
> | `FRONTEND_DEFAULT_LOCALE`    | Deprecated: set the site's **Default locale** instead. The variable is read only when the site has none, with a warning, and a later `0.y` removes it                                                                                                                                                                                                                                                                                    |
>
> **The Fediverse page moves.** It is no longer an entry of the admin's main menu: it is **Fediverse** under **Site** in the Micelio sub-navigation, for the roles that have `plugin::fediverse.read` as before. The host lists the plugin as always enabled in `config/plugins.ts` (the plugin reads `FEDIVERSE_ENABLED` itself) and its root admin app stops calling `registerFederationPanel` and `registerFediversePage`: see [configure.md](configure.md#what-the-host-provides).
>
> Keep `FEDIVERSE_ACTOR_IDENTIFIER`: it is the actor's address, and remote servers key your followers by it. The handle host must still answer WebFinger: the frontend's route does it on the site's domain, with no proxy rule.

What the release adds to the plan, from the building of the change:

- **A fresh database needs one more boot.** The step needs the default site, which the core creates in its own bootstrap, after this package's. A new instance works from the first boot (the identifier is `FEDIVERSE_ACTOR_IDENTIFIER`, the handle host the host of `URL`); the second boot writes the identifier and the hosts. An upgraded database has the site and is done on the first boot.
- **The username is locked while the actor has followers.** Content Manager → Sites answers `409` with the code `username-locked` to a change; on 0.6 it was free. Change it before you have followers, or not at all.
- **The first `Update(Person)`.** The first 0.7 boot sends one, because the actor now lists the CMS host in `attributionDomains`.
- **Roles.** The Content Manager lists the Fediverse profile and the **Fediverse actor** section to any role that can read `Site`, and lets any role that can update `Site` edit them. The profile is public in the actor document; the username and the identifier locks hold whoever edits.
